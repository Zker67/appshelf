# AppShelf

> **AI 助手**：请先阅读 [AGENTS.md](./AGENTS.md)，再开始任何操作。

## 项目简介

AppShelf 是个人软件图书馆：在一份可导入导出的软件清单里，用分类和标签整理自己收藏的 Windows 软件。在“发现”页一次搜索 winget、scoop 和 GitHub，一键加进清单；“本机已装”页列出电脑上已有的程序；“卸载”页按占用空间和上次打开时间挑出不要的程序卸载，并清理残留。它会对照本机已装的软件，按分类或标签多选，再逐个批量安装，之后持续检查更新；安装、更新和卸载的进度与日志都直接显示在任务面板里。

## 需求概述

### 核心需求

以下是实现状态；0.2.0 的用户测试按 [测试清单](./plans/2026-11-07-web-ui-and-discovery/06-design-and-acceptance.md#用户测试清单) 进行。

- [x] 软件清单：添加软件，配置分类和标签（一个软件一个分类、多个标签）
- [x] 软件备注：每个软件写自己的 Markdown 备注，边写边预览、停笔自动保存，任务清单可直接勾选；随清单导入导出，搜索也能搜到
- [x] 导入导出：清单就是一份 JSON 文件，可迁移、可备份；导入时合并
- [x] 本机检测：识别本机已有的软件（无论是否经 AppShelf 安装），已安装的不重复装，也不装错包
- [x] 批量安装：按任意分类或标签多选，点了就逐个安装（已装的自动跳过），每项单独显示结果，失败可单独重试
- [x] 检查更新：winget 和 scoop 用来源自己的更新信息（参考 UniGetUI）；GitHub 软件对比最新 release（参考 GitHub Store）
- [x] 自更新：v0.1.0 已发布到公开仓库 `Zker67/appshelf`，安装版检查新 release 后签名校验并升级；从 0.1.0 升到 0.2.0 的完整流程待实测
- [x] 安装来源：winget、scoop、GitHub Releases；不做离线安装包（scoop 还没有在装了 scoop 的机器上实测）
- [x] 发现软件：winget 和 scoop 边输边搜，GitHub 按需搜索；结果标出“已在清单”“本机已装”，winget 和 scoop 同名的合并为一行、在行内选来源；搜索框旁“加入到”设好默认分类和标签后，单个或多选一键直接加入（可撤销，Enter 也可加入），也可以加入后直接安装；GitHub 软件仍需确认检测规则；查不到时手动添加
- [x] 本机已装：列出 winget、scoop、注册表和应用商店里的程序，标出已在清单的和可更新的；有明确 winget / scoop 来源且可更新时可直接更新，也可加入清单；按“加入到”的分类和标签一键加入清单；没有来源的“查找来源”后带着检测规则加入；先显示注册表里的程序再补全来源，在 AppShelf 之外装卸软件后自动刷新
- [x] 任务进度与日志：每项显示阶段、下载进度和用时，日志实时显示在任务面板里，可跟随、复制，错误行高亮
- [ ] 卸载：按来源卸载（winget、scoop、应用商店，其余用程序自己的卸载程序，认得出安装程序类型时静默卸载），先预览命令、签名和提示，卸载后复查（真实卸载待用户选定测试程序后实测）
- [ ] 清理残留：卸载成功后查找留下的目录、设置、快捷方式和开机启动项，逐项列出判断依据，勾选后清理；文件进回收站，注册表先备份（待真实卸载后实测）
- [x] 软件信息：图标、简介、发布者、主页、许可证、最新版本和发行说明

### 技术选型

| 层级 | 技术 | 说明 |
|---|---|---|
| 桌面框架 | [MyGo](https://mygo.egoist.dev/)（`github.com/egoist/mygo`）v0.8.1 Web 页面窗口 | Go 绑定服务给页面调用，Windows 上用 WebView2 显示；版本由 `go.mod` 锁定 |
| 后端 | Go | 版本见 `go.mod`；另外依赖 `golang.org/x/sys`（读写注册表、提权启动安装程序、监听变化、移到回收站）和 `go.yaml.in/yaml/v3`（读 winget 清单文件） |
| 前端 | React 19 + TypeScript 7 + Tailwind CSS 4 + shadcn/ui | 在 `frontend/`，Vite+ 构建，Bun 管理依赖；只做展示，读写都通过 Go 服务 |
| 安装来源 | winget / scoop / GitHub Releases | 调用各自的官方能力，不自己写安装逻辑；winget 状态通过 PowerShell 模块 `Microsoft.WinGet.Client` 读取 |
| 数据存储 | JSON | 软件清单（可导入导出）和本机状态分开存放在 `%AppData%\AppShelf\` |
| 自更新 | MyGo updates | 发布到公开仓库 `Zker67/appshelf` 的 GitHub Release，更新包由私钥签名 |
| 测试 | `go test`、`vp test` | 绑定服务用假来源测试，不需要窗口；来源、本机已装、详情和图标有直接调用本机 winget、注册表、GitHub 的只读集成测试 |

## 功能特性

| 页面 | 功能 |
|---|---|
| 我的清单 | 左侧按状态、分类、标签筛选（分类和标签可多选、取并集，含“未分类”），在原处新建、重命名、删除分类和标签，底部导入、导出清单；列表可搜索、排序、Shift 连选、右键菜单，悬停直接安装或更新；多选后批量安装、更新、设分类、加标签、删除（可撤销）；右侧详情显示来源信息、检测规则和软件介绍，「备注」页签显示自己的 Markdown 备注 |
| 备注编辑 | 详情「备注」页签或右键“写备注”打开：编辑、分栏、预览三种显示，分栏时左写右看、预览跟随滚动；工具栏和 Ctrl+B / I / E / K 插入标记，回车续写列表，Tab 缩进；停笔约 0.6 秒自动保存，Ctrl+S 立即保存，关闭时保存 |
| 发现 | 左侧按来源（winget、scoop、GitHub）筛选结果；输入即搜 winget 和 scoop，回车或“搜 GitHub”再搜 GitHub；结果标出“已在清单”“本机已装”，winget 和 scoop 同名的合并为一行、行内切换来源，右侧看详情；搜索框旁“加入到”选好默认分类和标签，单个或多选“加入”（或按 Enter）直接放进去，toast 里可撤销；“加入并安装”加入后读到安装状态就开始安装；GitHub 软件弹窗确认检测规则（自动建议，位置已预填）；查不到就“手动添加” |
| 本机已装 | 启动默认页；先看概览（总数、来源分布、可更新、清单覆盖、无来源），点任意一块进入列表；按来源（winget、scoop、本机程序、应用商店）、更新（可更新、自动更新、已忽略）和清单（已在清单、未加入清单）三组组合筛选；单项或多选直接更新（点了就开始，不弹确认），无需先加入清单，行内设置更新方式；也可按“加入到”一键“加入清单”，或“查找来源”；按名称、占用空间或安装日期排序，宽窗口显示大小和安装日期；多选后也可以“卸载” |
| 卸载 | 左侧按占用空间（1 GB 以上、100 MB – 1 GB、100 MB 以下）、上次打开（一个月内打开过、1–6 个月没打开、半年以上没打开、没有打开记录）和来源组合筛选，标题显示合计大小；默认按占用空间排序，也可按久未打开、最近打开、名称；每行显示大小条和上次打开时间（取自 Windows 记录的开始菜单、任务栏、桌面启动，正在运行的算刚打开），行尾常驻“卸载”按钮，多选后显示选中的合计大小；卸载前先看卸载方式、命令、签名和提示再确认；“最近卸载”列出这次的卸载任务，可查找残留、改用卸载程序重试 |
| 更新 | 清单和本机的可更新软件合在一起，同一软件只出现一次，顶栏页签显示数量；软件图书馆自身的新版本在最上面；每个软件可选“提醒我 / 自动更新 / 忽略”，或跳过某个版本、7 天内不提醒；“全部更新”、自动更新列表、已忽略列表（可恢复）、最近更新记录；侧栏显示自动检查的间隔 |
| 编辑软件 | 名称、分类、标签；winget、scoop 搜索后选择精确的包；GitHub 填仓库、安装包匹配和安装参数，可“检查最新版本”；检测规则（GitHub 必填） |
| 任务（标题栏） | 逐个执行安装、更新和卸载，标题栏的进度环显示完成数；每项显示状态、阶段、下载进度、用时和原因，展开即看实时日志（跟随输出、复制、错误行高亮）；停止（当前项完成后）、继续、重试失败项、静默卸载失败后“打开卸载程序重试”、winget 更新失败后“打开安装程序重试”、安装程序不支持直接更新时确认“卸载后重新安装”、取消等待中或正在下载的任务（用户发起的任务排在自动更新前面）、顶部列出需要重启电脑才能完成的软件、卸载成功后“查找残留”、清除已完成、打开日志文件 |
| 清理残留 | 按“很可能 / 可能 / 不确定”分组，每项写明类型、路径和加减分的理由，默认只勾选“很可能”；清理后逐项显示结果，可打开注册表备份 |
| 设置（左侧栏底部） | 各来源是否可用（winget 缺模块时可一键安装）、GitHub 请求额度；更新：自动检查间隔、系统通知、关闭窗口后留在托盘（默认开）、开机启动；关于：版本、检查更新与去更新、自动检查新版本（启动时 / 定时 / 不自动）、数据和日志目录。发现新版本时窗口右下角提示，点「去更新」后台下载，装好自动重新打开 |
| 托盘图标 | 运行时常驻；单击打开窗口，右键可查看更新、全部更新、检查更新、打开任务、退出（有任务没完成时先确认）；有可更新的软件时右下角显示橙点，悬停显示可更新数量和正在执行的任务 |
| 使用说明（左侧栏底部，设置上方） | 分页签的上手步骤、状态说明、检测规则和快捷键 |

标题栏右侧还可以切换外观：跟随系统、浅色、深色。

防误装：状态读不准就不装；队列执行每一项前再查一次，已装的跳过；装完再查一次，查不到就记为失败；GitHub 安装包无法唯一确定时拒绝安装，下载后校验 SHA-256。

防误删：卸载前先预览并确认，执行前后各查一次，卸完还在就记为失败；不卸载 winget、scoop 和软件图书馆自己；残留从不自动清理，系统目录、共享目录和其他已装软件的目录不碰，文件进回收站，注册表先备份。

## 使用方法

只支持 Windows。需要 Go（版本见 `go.mod`）、Bun、WebView2 和 winget；scoop 可选。

```bash
bun install --cwd frontend      # 第一次运行前安装前端依赖
go tool mygo dev                # 开发模式，前端热更新
CGO_ENABLED=0 go test ./...     # Go 测试
bun run --cwd frontend check    # 前端格式、lint、类型检查
go tool mygo build              # 打包到 build/windows-amd64/：exe 和安装包
```

GitHub 软件较多时，建议在“设置 → 安装来源”填写 GitHub token（或设置环境变量 `GH_TOKEN` / `GITHUB_TOKEN`），否则每小时只有 60 次 GitHub 请求。完整说明见 [运行与部署说明](./docs/operations.md)。

## 配置说明

### AI 行为配置

- **协作入口**：`AGENTS.md`，AI 首次进入项目时先读取。
- **规则文件**：`.agents/rules/*.md`，使用 YAML frontmatter + Markdown。
- **MyGo 维护 Skill**：`.agents/skills/mygo-maintenance/`，由 `mygo init` 生成，用于升级 MyGo 版本。
- **目录说明**：`.agents/README.md`。

### 应用配置

- `mygo.json`：应用名、标识符、版本号、输出目录，自更新的公钥和 GitHub 仓库，以及安装包的中文（`installer.nsh`）。
- `CHANGELOG.md`：每个版本的更新说明，发布时成为 GitHub Release 的说明。
- GitHub token（可选）：在设置里填写，验证后加密保存在本机；也可以用环境变量 `GH_TOKEN` / `GITHUB_TOKEN`，两者都有时用设置里的。

### 项目文档

`docs/` 承载当前代码和程序的长期文档。同一类信息的主维护位置以 [单一信息源说明](./docs/architecture/source-of-truth.md) 为准。数据格式见 [API 与接口说明](./docs/api.md)。

### 外部参考

`references/` 记录 UniGetUI、GitHub Store、winget、scoop 等外部资料和借鉴点，见 [外部参考索引](./references/README.md)。

```text

├── AGENTS.md                 # AI 协作入口
├── README.md                 # 项目说明
├── CHANGELOG.md              # 更新说明（GitHub Release 显示）

├── references/               # 外部文档和外部仓库参考
```
