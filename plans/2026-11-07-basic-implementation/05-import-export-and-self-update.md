# 阶段 05：导入导出与自更新

状态：`[partial]`（导入导出完成；自更新的代码、配置和签名构建完成，等待创建公开仓库并发布 release）

## 一、导入导出

### 导出

设置页的“导出”按钮打开系统保存对话框，把当前 `catalog.json` 原样写到用户选的位置。只导出清单，不包括本机状态。

### 导入

1. 打开系统文件对话框，读取文件。
2. 按阶段 01 的规则完整校验，任何错误都整份拒绝，并显示第一个错误的位置和原因。
3. 计算合并结果，弹出确认框：新增几个软件、合并几个软件、新增几个分类和标签。
4. 确认后写入。

合并规则：

| 对象 | 规则 |
|---|---|
| 分类、标签 | 按名称匹配；同名视为同一个，不同名的新增 |
| 软件 | 按来源唯一键匹配（例如 `winget:Obsidian.Obsidian`） |
| 已存在的软件 | 保留本地的名称、分类、来源字段和检测规则；标签取并集；本地没有分类时采用导入的分类 |
| 新软件 | 新增，分类和标签映射到合并后的 ID |
| ID 冲突 | 导入的 ID 与本地重复但内容不同时，为导入项重新生成 ID |

### 成功标准

- 单元测试：导出后原样导入，结果不变；合并的各条规则；非法文件整份拒绝，本地清单不被修改。

## 二、AppShelf 自更新

使用 MyGo 的更新机制，不自己实现。

### 步骤

1. 用 `go tool mygo keygen` 生成签名密钥。私钥放在仓库外，由用户保管（密码管理器或 CI secrets），构建时通过 `MYGO_UPDATER_PRIVATE_KEY` 提供。
2. 在 `mygo.json` 中加入 `updates.publicKey`，以及发布位置（`github` 或 `url`，取决于总览“待用户决定”第 1 项）。
3. 应用中启用 `plugins/updater` 的原生 UI 版本（`plugins/updater/native`，具体用法在实施时按插件文档确认）：它会在后台检查更新，显示更新说明，并提供安装或稍后提醒。
4. 设置页“关于”里的“检查更新”调用同一个检查入口。
5. 新增 `CHANGELOG.md`。MyGo 从中读取每个版本的更新说明，格式为 `## 0.1.0`。
6. `docs/operations.md` 补充发布步骤：`go tool mygo build -upload`，上传后先是草稿，确认后再发布。

### 前提与限制

- 只有通过 MyGo 生成的安装包安装（装到 `%LOCALAPPDATA%\Programs`）的版本才能自更新；开发模式下 `Updater.Enabled()` 为 false。
- 验证自更新需要至少发布两个版本。创建远端仓库、上传、发布 Release 都是外部写操作，需要用户单独授权。

### 成功标准

- 代码和配置完成，`go tool mygo build` 能在有私钥时生成更新文件。
- 用户授权发布后：安装旧版本 → 发布新版本 → 旧版本提示更新并成功升级。没有授权之前，本部分标为 `[partial]`。

## 失败与回滚

导入相关的改动只影响 `internal/catalog` 和设置页。自更新的配置只在 `mygo.json` 和启动代码里；去掉插件和 `updates` 配置即可回到不带自更新的版本。
