# 详情栏压缩与分页签

状态：`[in-progress]`：实现与自动检查完成后，等待用户在真实窗口验收。

## 用户诉求

- 详情栏已经现代化，但内容竖着摞太长，不好阅读；要用现代化的方式处理。

## 实施

1. `components/detail-panel.tsx`
   - 头部：标题下新增 `subtitle`（来源 ID，等宽小字，带复制）；往下滚时头部收缩成一行（图标缩小、标题变小、徽章和 ID 收起），操作按钮一直可见，回到顶部再展开。
   - 新增 `DetailTabs`：分段式页签，滑块随选中项移动；每个页签自己滚动，切换时按方向滑入。只有一个页签时不显示页签条；页签还在读取时先占位，读完不需要时收起。
2. `components/package-info.tsx`
   - 「概览」：简介卡片 → 2 列信息格（最新版本、发布者、许可证、发布时间、星标、安装包）→ 一排链接按钮（主页、发布者、许可证、发行页、更新说明）→ 标签（超过 8 个收起）→ 版权小字。
   - 「介绍」：长介绍单独一个页签，按段落和列表排版，不再折叠。
   - winget 的 `releaseNotes` 是 `ReleaseNotesUrl` 链接，改为链接按钮，不再当正文显示。
3. 调用方
   - 发现页 `HitDetail`：ID 从信息行挪到标题下。
   - 我的清单 `ShelfDetail`：来源 ID 挪到标题下；分类、标签、状态说明留在「概览」；已装版本、最新版本并入信息格（最新版本以本机状态为准，不再显示两遍）；安装包、检测名称、检测路径、安装包匹配、安装参数、bucket 地址收进「安装规则」页签。

## 不变量

- 不改 Go 服务和数据结构；显示的信息和操作不增不减，只调整位置和样式。
- 详情只用于展示，不参与是否已装的判断。

## 验收

- `bun run --cwd frontend check`、`bun run --cwd frontend test` 通过。
- 用户在真实窗口确认：发现页 winget、scoop、GitHub 结果和我的清单的详情，页签切换、头部收缩、链接按钮、亮暗主题。
