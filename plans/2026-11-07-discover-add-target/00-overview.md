# 一键加入与发现页改进

状态：`[in-progress]`：实现与自动检查完成，等待用户在真实窗口验收。

## 用户诉求

- 发现页每次“加入”都要在弹窗里选分类、标签，太麻烦。应当有一个地方设好“加到哪里”，之后点加入直接加进去。
- 已在清单的“查看”按钮太素，按钮要优化。
- 同意一并实施后续建议：本机已装页共用默认位置、默认位置放在搜索框旁、winget 与 scoop 同名结果合并、GitHub 规则确认更快、键盘加入。

## 实施

1. 默认加入位置 `lib/add-target.ts`：分类 ID + 标签 ID，存在 `localStorage`，用模块级存储在各页之间共享；读取时去掉已删除的分类和标签。
2. `components/add-target.tsx`：搜索框旁的“加入到”按钮，显示当前分类和标签，点开选分类（含不分类、新建）和标签（含新建）；新建时立即创建，存下 ID。发现页和本机已装页的顶栏各放一个。
3. `state/quick-add.ts` 一键加入：
   - 来源不是 GitHub 时直接按默认位置调用 `Shelf.addPackages`，不弹窗；toast 说明加到了哪里，带“去清单查看”和“撤销”（撤销即从清单删除刚加入的项）。
   - 含 GitHub 时打开加入弹窗（必须确认检测规则），弹窗预先填好默认分类和标签。
   - “加入并安装”加入后打开现有的安装预览。
   - 加入中的行按钮禁用，直到清单标记它为已在清单；失败或撤销后恢复。后端 `catalog.Validate` 本来就拒绝来源相同的软件，前端禁用只是避免看到这个报错。
4. `components/row-actions.tsx`：行尾“加入”按钮显示目标位置提示；已在清单改为一个带勾和箭头的浅主色按钮“已在清单 →”，取代原来的“已在清单”标记加灰色“查看”。两个页面共用。
5. 合并同名结果 `lib/twins.ts`：显示全部来源时，winget 与 scoop 中名称相同（`fold` 后完全相等）的一对显示为一行，行内和详情里切换来源；默认选已在清单的那个，否则 winget。只按来源筛选时不合并。加入的仍是所选来源的精确包。
6. 键盘：`usePageKeys` 增加 Enter，发现页和本机已装页对当前项加入，已在清单的去清单查看。
7. 加入弹窗：不再自动聚焦第一个输入框；所有必填检测规则就绪（包括自动采用建议）时，焦点落在打开弹窗时的主按钮上，Enter 即可加入。
8. 使用说明、`README.md`、`frontend/README.md` 同步。

## 不变量

- 不改 Go 服务；GitHub 软件仍必须由用户确认检测规则，规则建议不跳过弹窗。
- 安装仍先预览、确认后逐项执行。
- 合并只影响显示，加入的来源仍是用户所选的精确包 ID。

## 验收

- `bun run --cwd frontend check`、`bun run --cwd frontend test` 通过。
- 用户在真实窗口确认：设好“加入到”后，发现和本机已装点“加入”直接进入对应分类和标签；重启后设置仍在，两个页面同步；删掉该分类后回落为“不分类”；撤销有效；GitHub 结果仍弹窗且已预填、规则就绪时 Enter 可加入；同名结果合并与来源切换；“已在清单 →”按钮观感；Enter 加入当前项。

## 回滚

改动只在 `frontend/` 和文档，按文件撤回即可。
