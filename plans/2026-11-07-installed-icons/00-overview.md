# 本机已装图标优化

状态：`[partial]`：0.2.1 技术交付完成；用户视觉验收、完整来源环境和真实安装验证仍保留边界。

发布入口：[v0.2.1](https://github.com/Zker67/appshelf/releases/tag/v0.2.1)。

## 目标与根因

已安装的 winget 软件当前先请求网络图标，再回退到本机；首次图标库请求最长等待 60 秒，远端图标下载每个最长 8 秒。应用商店并发图标请求会重复枚举开始菜单；只在开始菜单查找会漏掉无启动入口的软件包。失败下载缓存 24 小时，前端失败后不再尝试。

## 实施

1. 本机图标优先；合并本机提取和应用商店枚举，持久缓存成功结果并对文件变化失效。
2. 补应用商店包清单中的真实 Logo、本机安装目录的明确图标候选；不改安装检测。
3. 下载排队计入超时，临时失败短暂退避；前端失败后有限重试，并随本机列表刷新重新请求。
4. 定向回归测试覆盖无网络本机读取、并发去重、缓存失效、缺失图标回退和超时；最后运行项目检查并打包。

## 不变量与验证边界

图标只用于展示，所有文件与网络访问留在 Go。保留下载格式、大小和公网地址限制；不新增依赖、不修改用户清单、不执行安装。视觉和实际滚动体验由用户在真实窗口验收。

## 回滚

按本计划涉及的 diff 恢复代码；新增图标缓存可以重新生成，不影响清单或软件安装状态。

## 实施结果

- 已安装软件改为本机优先；成功提取持久缓存，按源文件变化失效，相同图标并发只提取一次。
- 应用商店扫描共享、后台预热，失败短暂退避；新增读取 Appx 清单 Logo，包括无开始菜单入口的包，PNG 直接读取不占用 UI 绘制线程。
- 图标库冷启动等待从 60 秒限制为 10 秒，下载排队纳入 8 秒超时，下载失败退避从 24 小时改为 2 分钟。
- 前端失败后最多重试 3 次；刷新本机列表变更图标 URL，已恢复的来源可以重新显示。
- 定向回归验证本机图标在网络已取消时仍返回；20 个并发请求只扫描一次、提取一次；重启复用缓存，文件变更后重新提取。额外覆盖提取失败恢复、包 Logo 路径与下载排队超时。
- 真实只读读取本机 152 个软件包 Logo，约 2.6 秒；此数字表示找到的有效 Logo 文件，不等同于全部本机软件的最终显示覆盖率。
- `gofmt -l .`、`go vet ./...`、`go tool mygo vet`、`CGO_ENABLED=0 go test ./...` 全部通过；前端格式、lint、类型检查和 12 项测试通过。
- `go tool mygo build -o build/icon-preview` 通过，生成可运行程序与安装包；没有签名或上传新版本。
- 用户验收：打开优化版“本机已装”，查看首次加载、滚动、刷新与重启后的速度和缺图标情况。没有真实图标资产的软件仍显示首字母，不保证全部都有图标。

## 后续缺失图标排查

排查已完成。以 UniGetUI 当前源码为参考，先读取真实清单并逐项执行图标服务，统计成功与缺失原因；补充已证实的来源缺口，禁止将发现本地资产的数量当成图标实际读取成功率。保留前轮未提交改动。

### 缺失项复核结果

- 参考 [UniGetUI 源码复核](../../references/external-repos/Devolutions__UniGetUI/README.md#图标来源复核2026-11-07)，补充 MSI ProductIcon、同名主 EXE、开始菜单匹配和明确注册表 winget 便携包 ID 的图标库回退；仅影响展示，不改安装检测。
- 同一份本机注册表清单真实调用图标服务：175/209 → 191/209，新增找回 16 项，包括 Blender、FlClash、MicaPDF、Quicker、QuickLook、Node.js、File Converter、Godot Engine 等。
- 前轮检查曾报告缺少 Microsoft.WinGet.Client，因此当时统计是注册表回退清单，不代表完整 winget 清单或 scoop 覆盖率；没有安装模块或软件。
- Appx 原生注册表扫描替代 PowerShell，152 个 Logo 文件保持可读取，单次实测约 0.10 秒（原读取约 2.6 秒）。额外通过图标服务逐项请求与 PNG 解码验证，而非只检查路径存在。
- 仍有 18 项没有定位到可可靠匹配的独立图标，主要是 CLI 和系统组件，也包括 PostgreSQL；保留首字母回退，不把其他软件或通用 EXE 图标硬配上去。当前案例含 fd、ripgrep、cloudflared、GitHub CLI、VC++ 运行库、GameInput、SDK 组件等。
- 逐项审计的本机名称与路径只保存在系统临时目录，不放入仓库；临时诊断程序已删除。
- 该阶段预览产物为 `build/icon-preview-2/windows-amd64/AppShelf.exe`；正式交付版本为 0.2.1，构建到 `build/publish-v0.2.1/`，用既有更新私钥签名；没有把用户视觉验收标为通过。

## 0.2.1 收口与发布

发布前阻断已修复：用户窗口只有 209 项“本机”且无可更新项。现场确认模块实际已安装，但 Go 子进程继承 PowerShell 7 的 PSModulePath，Windows PowerShell 5.1 没有搜索自己的用户模块目录。先补子进程模块路径回归测试与局部修复，再验证完整来源分类和更新数；同时保留来源不可用原因，避免静默降级。

- 5 个剩余 CLI（GitHub CLI、cloudflared、fd、ripgrep、rustup）真实 EXE 的 PE 资源中没有 RT_GROUP_ICON；不能从它们自身提取独立图标。
- 其余 12 个组件及 PostgreSQL 缺少明确的注册图标、无歧义开始菜单匹配或其他可靠入口；保留回退显示，不将发现的其他程序图标配到它们上面。没有承诺所有软件都有品牌图标。
- Go 和前端版本统一为 0.2.1；更新日志、README、图标服务文档、来源参考和计划索引同步。
- Go 格式、vet、MyGo vet 与全部测试，前端格式、lint、类型和 12 项测试通过；152 个 Appx 图标响应完成 PNG 解码验证。
- 发布包含安装包、完整签名更新包、增量更新、更新清单、安装脚本与 SHA256SUMS；核对本地签名、附件散列和标签对应提交后设为正式 Latest。
- 自更新实际替换程序、真实安装和用户窗口体验仍待相应验收；源码检查和签名验证不替代用户验收。

### 来源失效根因与验证

- 模块实际已经安装。Go 从 PowerShell 7 继承 PSModulePath，直接启动 powershell.exe 时缺少 Windows PowerShell 5.1 的用户模块搜索目录，导致误报模块不存在；这不是软件来源或安装状态被修改。
- 在 runner 的子进程脚本中恢复 Windows PowerShell 的标准模块目录，保留自定义目录，不改父进程或系统环境，不重装模块。先用隔离 PSModulePath 的真实子进程测试复现失败，修复后验证通过。
- 来源读取失败或不可用的原因保留到本机列表 Notes；已有页面提示可展示降级原因。
- 真实查询恢复到 318 项：winget 147、应用商店 101、本机 70，25 项有来源报告的更新；前轮 191/209 图标统计仅属于降级快照。
- 该修复纳入 0.2.1；签名包重新构建，发布附件不得使用此前的旧构建。

- 修复来源环境后的完整清单另外审计：318 项中 271 项图标响应成功，47 项回退（winget 32、应用商店 9、本机 6）。该结果与前轮注册表快照的 191/209 分别记录，不混用成功率；尚未接入的官方图标元数据和无可靠匹配资源属于已知限制。
