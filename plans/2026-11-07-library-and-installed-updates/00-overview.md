## 用户决定

- 左上角显示“软件图书馆”。
- 未加入清单的软件也允许更新，覆盖从本机列表识别出的 winget / scoop 软件；仍需预览、确认并逐项执行。
- 原“只更新清单内软件”的约定由本次明确要求覆盖。直接更新不将软件自动加入清单。

## 实施与不变量

1. 修复 React Activity 恢复 Effect 时把已缓存图片重置为 loading 的问题；URL 不变保留状态，恢复后核对图片 complete/naturalWidth。增加独立组件回归入口，不使用业务假数据或截图替用户验收。
2. 修改左上角名称和窗口标题。
3. 新增本机更新预览和启动接口，只接收内部清单 key，在 Go 端重新解析精确来源。复用现有串行队列，执行前后复查；更新不得退化成安装，状态不明或来源外安装时拒绝执行。
4. 单项与多选均可更新，已有清单项复用其身份，任务按来源去重；本机状态刷新后展示新版本。
5. 假来源测试验证清单与状态不被添加、源身份校验、无可用更新/状态未知时不执行、更新成功与重试、并发去重。
6. 同步 AGENTS、README、API、使用说明和计划索引；完成 Go/前端检查、构建和签名验证再发布。真实安装或更新软件仍需指定测试目标，不用用户机器执行未指定的更新测试。

- 图标组件以 URL 作为状态边界；Activity 恢复时读取现有图片 complete/naturalWidth，不再重置已完成状态。独立浏览器组件中首次解码与一次隐藏恢复后均为 complete=true、naturalWidth=32、opacity-100；后续自动浏览器检查受扩展 UI 阻挡，未宣称用户窗口视觉验收通过。
- 左上角、窗口标题与关于信息统一改为软件图书馆。
- 单项和多选本机更新接入现有预览与任务面板；Go 只按服务端本机 key 解析来源，批量预览分来源一次读取，队列每项执行前后复查。
- 已通过假来源测试：清单外更新成功且不创建清单/状态文件，失败后重试仍为 Upgrade，未知 key / 无来源 / 未安装 / 未知 / 来源外 / 无更新 / 取消 / 预览后状态变化均不执行；清单内复用身份，跨 ID 同来源不能重复排队；scoop 批量预览和两次执行复查覆盖。
