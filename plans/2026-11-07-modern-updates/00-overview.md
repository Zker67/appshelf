# 现代化的软件更新

状态：`[in-progress]`：6 个阶段已实现并通过自动检查，等待用户在真实窗口验收；真实软件的自动更新未实测。

## 用户诉求

- “本机已装”里的更新状态和清单状态分开筛选。
- 可以设定软件定期更新，也可以忽略更新。
- 更新体验更现代，对新手更友好。

用户在分析后确认“都做好”，并要求先把计划写进 `plans/`。本计划覆盖 [基本实现](../2026-11-07-basic-implementation/00-overview.md) 和 [Web 前端](../2026-11-07-web-ui-and-discovery/00-overview.md) 中“忽略或跳过更新、后台定时检查和托盘通知、自动安装更新”这几项非目标，由用户本次明确要求。

## 已确认的假设

1. “状态分开”指本机已装页的筛选维度，不是存储层：存储层的清单（`catalog.json`）与本机状态（`state.json`）本来就分开。
2. 每个软件的更新方式（自动更新 / 提醒我 / 忽略）、跳过的版本和暂缓期限是本机状态，存放在 `state.json`，以来源 key（如 `winget:git.git`、`scoop:main/7zip`、`github:cli/cli`）为键，不随清单导出；未加入清单的本机软件也能设置。
3. `state.json` 只新增可省略的字段，按 `docs/api.md` 的兼容规则不升级 `schemaVersion`：旧版本读取时忽略这些字段，不会把文件当成损坏而改名。
4. 自动更新只用于用户逐个开启的软件，并且要同时满足：来源是 scoop，或用户范围（注册表 HKCU）安装的 winget 软件；版本已知；不是来源外安装；它的程序当前没有在运行。GitHub 软件的安装程序会弹窗并可能要求管理员权限，机器范围的 winget 软件会弹 UAC，这两类只提醒，不自动更新。
5. 定期检查默认每 6 小时一次，只在 AppShelf 运行时有效。关闭窗口后留在托盘、开机时在后台启动，这两项默认关闭，由用户在设置里打开。系统通知默认开启，只在窗口不在前台时发出。
6. 本次只做本地修改和非破坏性验证，不升版本号、不提交、不发布。涉及真实软件的自动更新不在用户机器上执行；用假来源测试。

## 设计

### 更新策略（本机状态）

`state.json` 新增：

- `updates`：`{ "<来源 key>": { "mode": "auto" | "ignore", "skip": "<版本>", "until": "<时间>", "name": "<名称>" } }`。`mode` 省略表示“提醒我”。
- `history`：最近 200 条更新记录 `{ key, name, from, to, result, message, auto, at }`。

一个可用更新在以下情况算“已忽略”，不计入可更新数量和“全部更新”，单独列在“已忽略”里，可以恢复提醒：

- `mode` 为 `ignore`（一直不更新）；
- `skip` 等于来源给出的最新版本（跳过这个版本，出了更新的版本会再提醒）；
- `until` 晚于现在（暂缓，默认 7 天）。

用户直接对一个已忽略的软件点“更新”仍然可以执行：这是明确操作，照样先预览再确认。

### 统一更新列表

新服务 `Updates` 把清单软件（来源状态为可更新且不是来源外安装）和本机已装的 winget / scoop 程序（有新版本）按来源 key 合并去重；同时在清单里的，使用清单里的软件身份。每项给出名称、图标、来源、当前版本和新版本、是否大版本升级（第一个版本号数字变大）、更新方式、忽略原因、是否能自动更新及原因、程序是否正在运行、是否在任务中。AppShelf 自身有新版本时（MyGo updater 的 `AvailableVersion`）单独显示一张卡片，点击后打开自更新窗口。

预览和执行：清单软件走 `core.Preview`，未加入清单的本机软件走 `core.PreviewUpdates`。两者合并显示在同一个预览弹窗里，确认后按队列逐项执行，执行前后复查，失败可以重试。

### 定期检查与自动更新

- 一次“检查”：重读清单状态（`core.Refresh`）和本机列表，两者都结束后算完成，记录完成时间，并按设置排好下一次检查。启动时的读取也算一次检查。
- 检查结束后：
  1. 对“自动更新”且满足条件的软件，按上面的预览路径加入队列，并标记为自动。
  2. 有新发现的可更新软件（同一个版本只提醒一次），且窗口不在前台时，发一条系统通知“发现 N 个软件可以更新”；点击通知打开窗口并切到“更新”页。
  3. 自动更新的任务全部结束后，再发一条通知“已自动更新 N 个软件”，失败时注明失败个数。
- 程序是否在运行：枚举当前进程的可执行文件路径，看有没有落在软件的安装目录下。安装目录取自注册表的 `InstallLocation`，没有时取 `DisplayIcon` 所在目录；scoop 软件取 `<scoop>\apps\<name>`。读不到目录时视为“无法确认”，不自动更新。预览中也提示“正在运行，更新时可能被关闭”。

### 设置（`settings.json`）

`updates`：`{ "checkEvery": "off" | "1h" | "3h" | "6h" | "12h" | "24h", "quiet": bool, "background": bool }`。默认每 6 小时检查、发通知、不留托盘。开机启动用 MyGo 的 `SetOpenAtLogin`，状态由系统保存，不写进 `settings.json`。AppShelf 自身的自动检查和自动下载沿用 MyGo updater 的偏好（`SetAutomaticChecks`、`SetAutomaticDownloads`）。

### 托盘与开机启动

开启“关闭窗口后留在托盘”后：创建托盘图标（由 `logo.png` 缩成 32×32），关闭窗口时只隐藏；托盘菜单有“打开软件图书馆”“检查更新”“退出”，单击图标打开窗口。开机启动时如果开了托盘，窗口在后台隐藏启动；没开托盘就正常显示窗口。

### 更友好的失败说明

winget 退出码按官方 `returnCodes.md` 补全中文说明（磁盘已满、需要联网、需要重启、文件被占用、被组织策略阻止、安装程序不支持更新、缺少依赖、已安装更高版本等）。

## 不变量

- 绝不误装：自动更新只调用 `Upgrade`，复用队列的执行前后复查；状态不明、来源外安装、未安装时都不执行，也不会退化成安装。
- 清单与本机状态分离：更新策略和历史记录只在 `state.json`，不随清单导出导入。
- 自动更新只针对用户逐个开启的软件；这个开启本身就是用户对该软件后续更新的确认。其余更新仍然先预览、再确认。
- 前端只做展示：是否可以自动更新、是否正在运行、是否已忽略，都由 Go 判断；前端只传来源 key，Go 端重新解析来源，前端不能注入新的来源 ID 或安装参数。
- 不在后台弹出 UAC：需要管理员权限或可能弹窗的来源不自动更新。
