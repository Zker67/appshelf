# 阶段 04：发现软件（统一搜索、详情、快速加入）

状态：`[partial]`：已实现，用户验收与运行验证边界见 [实施报告](./09-implementation-report.md)。

## 目标

在一个页面里搜到软件、看清是什么、一步加进清单，把“加软件”从现在的五六步缩短到两步：搜索 → 加入。查不到时才手动添加。

## 页面

```text
┌ 发现 ─────────────────────────────────────────────────────────┐
│ [ 搜索软件名称或 ID…                        ] [搜 GitHub]       │
│ 来源：全部 · winget 23 · scoop 5 · GitHub —                     │
├───────────────────────────────────────────────────────────────┤
│ ☐ [图标] Obsidian              Obsidian.Obsidian · winget  1.9.2 │
│          Obsidian 公司 · 知识库与笔记           本机已装  [加入] │
│ ☐ [图标] Obsidian Clipper …                                       │
│ …                                                               │
├───────────────────────────────────────────────────────────────┤
│ 已选 3 项                         [加入清单]  [加入并安装]       │
│ 查不到？手动添加                                                │
└───────────────────────────────────────────────────────────────┘
```

- 每个结果显示：图标、名称、精确 ID 和来源、版本、发布者（有时）；状态标记为“本机已装”“已在清单”。
- 点结果打开右侧详情面板，见下文“详情”。
- 顶部导航栏也放一个搜索框，任何页面里输入后按回车，都跳到“发现”并开始搜索。

## 搜索

| 来源 | 方式 | 何时执行 | 数量 |
|---|---|---|---|
| winget | `Find-WinGetPackage -Query <q> -Source winget`（本机实测 0.1–0.2 秒，含 PowerShell 启动约 0.8 秒） | 输入停顿 0.4 秒后自动执行，至少 2 个字 | 前 50 项 |
| scoop | `scoop search <q>`（先转义） | 同上，本机装了 scoop 才执行 | 前 30 项 |
| GitHub | `GET /search/repositories?q=<q> in:name,description&sort=stars`，按星标排序 | 只在搜索框里按回车或点“搜 GitHub”时执行：未登录每分钟只有 10 次搜索 | 前 10 项 |

- `Discover.Search(query, results *mygo.Channel[SearchBatch])` 按来源分批返回，先到先显示；新的搜索开始时，Go 端取消上一次还没结束的搜索。
- 排序：名称或 ID 完全相同的排最前，其次是前缀相同的，其余保持来源自己的顺序。
- 每个结果用“本机已装”索引（阶段 03）和清单对照：winget ID、scoop 软件名或 GitHub 仓库相同即为“已在清单”，这一项的按钮变成“已在清单”，不能再加。
- winget 结果的发布者：在同一个脚本里对前 20 项调用 `GetPackageVersionInfo` 读取，总耗时超过 0.3 秒时改为只在详情里显示。
- 某个来源出错只影响它自己那一组，组标题显示原因，例如“GitHub 额度已用完，14:05 恢复”。

## 详情

| 来源 | 来源数据 | 显示 |
|---|---|---|
| winget | winget-pkgs 仓库的清单：`raw.githubusercontent.com/microsoft/winget-pkgs/master/manifests/<ID 首字母小写>/<ID 按点分成目录>/<版本>/`，先读版本清单拿 `DefaultLocale`，再读该语言的清单；有 `zh-CN` 时优先 | 名称、发布者、简介、主页、许可证、发行说明链接、标签、版本 |
| scoop | `scoop info <bucket>/<name>` | 简介、主页、许可证、版本 |
| GitHub | 仓库信息（`GET /repos/<repo>`），以及最新 release 和自动选中的安装包（已有的 `DescribeGitHub`） | 简介、主页、许可证、星标、最新版本和发布日期、将安装的安装包；选不出安装包时显示原因 |

- 详情缓存在 `PathCache` 下，7 天过期；读取失败只显示“详情暂时无法读取”，不影响加入和安装。
- 解析 winget 清单需要一个 YAML 库，这是本计划唯一新增的 Go 依赖（实施时选维护中的版本，例如 `go.yaml.in/yaml/v3`）。

## 加入清单

1. 点“加入”，或多选后点底部“加入清单”，弹出小弹层：
   - 分类：下拉选择，可以直接输入新分类名并创建；
   - 标签：多选，可以直接输入新标签并创建；
   - GitHub 来源多一项检测规则，见下一节。
2. 确认后写入清单：名称用软件名，来源带精确 ID，与手动添加走同一套校验。批量加入时逐项保存，失败的项单独显示原因，其余照常加入。
3. “加入并安装”：加入后直接打开与“我的清单”相同的安装预览，确认后才排队。
4. 加入后列表里这几项变成“已在清单”，右下角提示“已加入 3 个软件”，并带“去清单查看”。

## GitHub 来源的检测规则建议

GitHub 来源必须有检测规则，手写正则太麻烦，所以加入时自动给出建议：

1. 本机已装列表里，显示名包含仓库名、或发布者与仓库 owner 一致的项，列为候选；选中一项后，用它的显示名生成规则（与阶段 03 第 5 步同一套规则）。
2. 没有候选时，用仓库名生成，例如 `^Obsidian`，并提示“安装后会用它判断是否已装”。
3. 规则可以修改，保存前照常校验。

## 手动添加

结果列表底部始终有“查不到？手动添加”，打开现有的编辑框（与 0.1.0 相同的字段），名称预先填入搜索词。原来编辑框里的来源搜索保留，便于修改已有软件的来源。

## 服务和事件

| 方法 | 说明 |
|---|---|
| `Discover.Search(query, ch)` | winget 和 scoop，分批返回 |
| `Discover.SearchGitHub(query)` | 单独执行，返回结果和额度 |
| `Discover.Details(source, ref)` | 详情，带缓存 |
| `Discover.SuggestRule(repo)` | GitHub 检测规则候选 |
| `Discover.Add(items, categoryID, tagIDs, newCategory, newTags)` | 加入清单，返回每项结果 |

## 成功标准

- 集成测试（只读，真实来源）：winget 搜“Visual Studio Code”能得到 `Microsoft.VisualStudioCode`；读取它的详情有发布者和主页；GitHub 搜索有结果（额度不足时跳过）；本机装了 scoop 时 scoop 搜索有结果。
- 单元测试：结果排序；与清单、本机已装的对照；winget 清单路径拼接（多段 ID，例如 `Microsoft.VisualStudio.2022.Community`）；YAML 解析与语言回退；检测规则建议。
- `Discover.Add`：批量加入时一项校验失败不影响其他项；加入后清单里来源键唯一。

## 失败与回滚

- winget-pkgs 清单读不到（网络受限）时，详情只显示搜索结果里已有的字段，不改用解析 `winget show` 的本地化文本。
- 自动搜索导致 PowerShell 进程过多时，改为常驻一个 PowerShell 进程处理搜索请求，并在本文件记录。
- 本阶段新增 `Discover` 服务和“发现”页，回退时删除即可，不影响清单和安装。
