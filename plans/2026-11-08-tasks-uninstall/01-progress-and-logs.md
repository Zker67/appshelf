# 阶段 1：任务进度与软件内日志

## 目标

1. 运行中的任务显示阶段（检查 → 下载 → 安装 / 更新 / 卸载 → 复查），能读到时显示下载字节和百分比。
2. 任务的输出在任务面板里实时显示，不用打开文件；日志文件照常保留。
3. 标题栏任务入口显示整体进度（如 `3/8`），关掉面板也能看到。

## 实测依据

- winget 输出被重定向时没有进度条，只有本地化的阶段文字（中文系统：“正在下载 <URL>”“已成功验证安装程序哈希”）。安装包下载到 `%TEMP%\WinGet\<Id>.<版本>\`（本机实测）。
- scoop 的阶段文字是固定英文（`Installing`、`Downloading`、`Checking hash`、`Extracting`、`Linking`、`Creating shim`、`Uninstalling`）。
- GitHub 安装包由 AppShelf 自己下载，字节数和总大小都准确。

## 设计

| 部分 | 实现 |
|---|---|
| 进度类型 | `source.Progress{Stage, Done, Total}`；来源用 `source.ReportProgress(log, p)` 报告，日志写入器实现了 `source.ProgressReporter` 才生效，来源接口不变 |
| 日志 | 新包 `internal/tasklog`：`Log` 把原始输出写进文件，同时整理成行（处理 `\r` 覆盖、去掉 ANSI 和 spinner、合并连续空行），内存里保留最后 2000 行；`Lines(from)` 按游标增量读取，另给出正在刷新的“当前行” |
| 队列 | `Item.Stage` 由队列设置（检查、复查）；运行中由来源报告；`Items()` 带出进度；进度和新行的通知节流到 250 毫秒，只标记 `tasks` 变化 |
| winget | 看到 URL 行进入“正在下载”，下载期间每 0.5 秒统计 `%TEMP%\WinGet\<Id>.<数字开头>` 的大小；URL 之后的下一行进入“正在安装 / 更新” |
| scoop | 按阶段文字切换阶段 |
| GitHub | 下载计数报告字节和总大小，然后“校验”“运行安装程序” |
| 接口 | `TaskEntry` 增加 `stage`、`done`、`total`；`Tasks.Log(id, from)` 返回 `{lines, next, start, live, done}` |
| 前端 | 任务卡片：阶段文字、进度条（有总大小时确定进度，否则流动条 + 已下载大小 + 已用时间）、展开日志（运行中自动跟随底部，往上翻时暂停跟随）、复制日志、打开日志文件；失败的任务默认展开最后几行并高亮错误行；标题栏任务按钮显示 `完成/总数` 与环形进度 |

## 不变量

- 日志文件内容与原来一致（原始输出），软件内显示的是整理后的行。
- 进度通知只标记 `tasks`，不让清单、来源跟着重读。

## 验收

- `tasklog` 单元测试：`\r` 覆盖、CRLF、ANSI、spinner、环形截断、游标。
- `queue` 测试：阶段变化、进度通知节流、`Items()` 带出进度。
- `api` 测试：`Tasks.Log` 的增量读取。
- winget 进度解析、scoop 阶段识别的单元测试（用实测输出样本）。
- 用户在真实窗口看一次安装：阶段、进度、日志滚动。

## 回滚

回退本阶段改动；日志文件格式未变。
