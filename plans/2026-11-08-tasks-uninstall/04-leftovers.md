# 阶段 4：卸载后的残留清理

## 目标

卸载成功后，可以在任务卡片里“查找残留”：列出可能的残留，每项附打分理由，用户逐项勾选后清理。

## 扫描范围（首期只扫低风险位置）

| 位置 | 判断 |
|---|---|
| 原安装目录 | 仍存在即列出 |
| `%ProgramFiles%`、`%ProgramFiles(x86)%`、`%ProgramData%`、`%AppData%`、`%LocalAppData%`、`%LocalAppData%\Programs` | 下一层或“发布者\名称”两层，名称与软件名或发布者相符的目录 |
| `HKCU\Software` | `<名称>`、`<发布者>\<名称>`、只含该软件的 `<发布者>` |
| 开始菜单（当前用户、所有用户）、桌面（当前用户、公用） | 指向原安装目录或目标已不存在且名称相符的快捷方式；同名的开始菜单文件夹 |
| `HKCU\…\CurrentVersion\Run` | 命令指向原安装目录的启动项 |
| scoop | `persist\<名称>` 目录 |

不扫描：COM、防火墙、AppCompat、EventLog、UserAssist、`HKLM`（需要管理员，误删代价大）。

## 打分（借鉴 BCU 的 `ConfidenceRecords`）

| 依据 | 分值 |
|---|---|
| 明确关联：就是原安装目录、快捷方式或启动项指向它 | +4 |
| 名称完全相符 | +2 |
| 名称只是部分相符 | −2 |
| 在发布者目录下 | +2 |
| 目录为空 | +4 |
| 目录里还有可执行文件 | −4 |
| 文件很多（超过 200 个） | −2 |
| 还有其他已装软件同名或同发布者 | −4 |
| 快捷方式的目标已不存在 | +2 |

4 分及以上为“很可能”，默认勾选；1–3 分为“可能”，0 分及以下为“不确定”，默认都不勾选。

## 保护

从不列出：Windows 目录、各已知文件夹本身（Program Files、AppData、桌面、文档等）和用户目录、盘符根目录、AppShelf 的程序和数据目录、包含或位于其他已装软件安装目录中的路径。清理前对每项重新检查保护规则和是否仍存在。

## 清理

- 文件、目录、快捷方式：移到回收站（`SHFileOperationW`，`FOF_ALLOWUNDO`）；Program Files 等位置需要管理员时由系统弹出确认。
- 注册表键、启动项：先用 `reg export` 导出到 `<数据目录>\backups\leftovers-<时间>-<名称>\`，再删除。
- 扫描结果保存在 Go 端（令牌），前端只能按编号选择，不能传入路径。

## 接口与界面

- `Tasks.FindLeftovers(id)`：只对成功的卸载任务；`Tasks.CleanLeftovers(token, ids)`：返回每项结果和备份目录；`Tasks.OpenBackup(token)`。
- 残留弹窗：按“很可能 / 可能 / 不确定”分组，每项显示种类图标、路径、分数和理由；底部“清理 N 项”，注明注册表先备份、文件进回收站；清理后显示每项结果和“打开备份”。

## 验收

- 打分和保护规则的单元测试。
- 真实环境：在临时目录造出“安装目录”“AppData 目录”“快捷方式”，在 `HKCU\Software\AppShelfTest-<随机>` 造注册表键和启动项（测试用独立的 Run 键路径），扫描出预期项目、保护项不出现；清理后注册表有备份、键已删除、文件进了回收站（测试会在回收站留下一个测试文件）。
- 用户验收：卸载一个测试软件后查找并清理残留。

## 回滚

回退本阶段改动；备份目录保留在数据目录中。
