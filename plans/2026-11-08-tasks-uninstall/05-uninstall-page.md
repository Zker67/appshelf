# 阶段 5：独立的卸载页

## 背景

用户试用后反馈（2026-11-09）有三点：

1. 卸载应该有自己的页签。
2. 「本机已装」行尾只在悬停时出现的卸载图标，和“更新”按钮风格不一致，也不好找。
3. 卸载时在乎的是占用空间和安装了多久，不是有没有更新。

## 设计

| 部分 | 实现 |
|---|---|
| 页签 | 标题栏第五个页签“卸载”，排在“更新”之后。图标是自绘的垃圾桶：悬停时盖子掀一下；选中时盖子反复打开，一个小盒子落进去 |
| 侧栏 | 全部程序；最近卸载（本次运行的卸载任务）。另有三组可以组合的筛选：<br>占用空间：1 GB 以上 / 100 MB – 1 GB / 100 MB 以下 / 大小未知<br>安装时间：30 天内 / 1 年内 / 1 年以前 / 日期未知<br>来源。<br>“未知”两项只在有程序时显示 |
| 工具条 | 当前筛选名、程序数和合计大小（只计注册表登记了大小的）、搜索、排序（占用空间、最早安装、最近安装、名称，默认占用空间，存进 `uninstall.sort`）、重新读取 |
| 行 | 图标、名称和版本、来源和发布者、“在清单里”标记。<br>右侧依次是：大小和大小条（按平方根缩放，颜色分档），安装时间（“3 个月前”加日期，1 年以前标为警示色），常驻的“卸载”按钮（与“更新”同样是带文字的描边按钮，悬停时变红）。<br>排队或正在卸载的显示“等待卸载 / 卸载中”。不显示更新信息 |
| 多选 | 选择栏的“卸载 N 个 · 合计大小” |
| 最近卸载 | 每项显示状态和原因，可以“查找残留”“打开卸载程序”“重试”，也可以去任务面板看日志 |
| 本机已装 | 去掉悬停才出现的卸载图标；多选栏的“卸载”保留 |
| 使用说明 | 新增“卸载”一节 |

纯逻辑在 `frontend/src/lib/uninstall.ts`：分档、相对时间、筛选、排序、合计、卸载任务，并有单元测试。不需要改 Go 接口。

## 验收

- `bun run --cwd frontend check`、`bun run --cwd frontend test`，以及 `go tool mygo build`。
- 用户在真实窗口检查：
  - 页签图标的动画；
  - 各组筛选的组合和计数；
  - 大小条和日期列；
  - 常驻的卸载按钮；
  - 多选时的合计大小；
  - 最近卸载里的残留入口。
