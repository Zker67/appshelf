# 常驻托盘与托盘菜单

> 状态：`[in-progress]`：已实现并通过自动检查，等用户在真实窗口验收
>
> 来源：用户 2026-11-09 参考 vibe-atlas 后要求「我们要有系统托盘和对应功能」。

## 现状（改之前）

- 托盘图标只在打开「关闭窗口后留在托盘」后才出现，这个开关默认关闭。
- 菜单只有「打开软件图书馆 / 检查更新 / 退出」，图标看不出有没有更新、有没有任务在执行。

## 目标

- 托盘图标在 AppShelf 运行时一直显示（与 vibe-atlas 一样常驻）；「关闭窗口后留在托盘」改为默认打开，关掉后关闭窗口就退出。
- 单击图标打开窗口；右键菜单：
  - 打开软件图书馆
  - 查看更新（N）：打开窗口并切到「更新」页
  - 全部更新（N 个）：与「更新」页的「全部更新」相同，排队所有可更新、没有被忽略、还没排队的软件；没有可更新的软件时不可点
  - 检查更新：检查期间显示「正在检查更新…」，不可点
  - 任务（N 项进行中）：打开窗口并展开任务面板
  - 退出：还有任务没有完成时先弹系统对话框确认
- 有可更新的软件（含 AppShelf 自身）时，图标右下角显示橙色圆点。
- 悬停提示显示可更新数量、正在检查，以及正在执行的任务和排队数量。

## 不变量

- 「全部更新」走 `startUpdates`，与更新页按钮相同：Go 重新核对，只排队能执行的，复用队列的执行前后复查；不弹预览确认（用户要求只有卸载需要确认）。
- 托盘只读状态、调用已有的服务，不新增判断是否已装的逻辑。
- 托盘的状态刷新最多每 0.5 秒一次，不跟着任务进度的高频变化重算更新列表。

## 实现清单

| 位置 | 内容 |
|---|---|
| `internal/api/tray.go` | `TrayStatus`（可更新数、可全部更新数、是否在检查、任务数、正在执行的任务和动作）；`UpdateAll` |
| `internal/api/settings.go`、`updates.go` | `settings.json` 的 `updates.background` 换成 `exitOnClose`（默认 false，即默认留在托盘）；没有托盘的版本保留原值 |
| `tray.go` | 常驻图标、按最近一次状态生成的右键菜单、悬停提示、带圆点的图标（`trayBadge`）、退出确认 |
| `main.go` | `Emit` 同时通知页面和托盘；`showPage`；「全部更新」后发系统通知，点击打开任务面板 |
| `frontend/src/App.tsx` | `navigate` 事件收到 `tasks` 时打开任务面板 |
| `frontend/src/components/dialogs/settings-dialog.tsx` | 「关闭窗口后留在托盘」的说明随开关变化 |

## 验收标准

- `go vet ./...`、`go tool mygo vet`、`CGO_ENABLED=0 go test ./...`、`bun run --cwd frontend check`、`bun run --cwd frontend test` 通过，`go tool mygo build` 能打包。
- 用户在真实窗口验收：
  1. 启动后托盘一直有图标；关闭窗口后窗口隐藏、图标还在；设置里关掉「关闭窗口后留在托盘」后，关闭窗口即退出。
  2. 有可更新软件时图标右下角有橙点，悬停显示「N 个软件可更新」；右键菜单各项的数字和可点状态正确。
  3. 「查看更新」「任务」打开窗口并到对应位置；「全部更新」开始更新并弹出系统通知。
  4. 有任务在执行时点「退出」先弹确认，选「取消」不退出。

## 回滚说明

`tray.go` 恢复成按开关创建和销毁图标、三项菜单；删除 `internal/api/tray.go`；`settings.json` 字段改回 `background`（`exitOnClose` 会被忽略，回到默认不留托盘）。
