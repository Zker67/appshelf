# 修复卸载误报失败

状态：`[in-progress]`：实现与自动检查完成后，等待用户真实卸载验收。

## 现象

1. 卸载一个 winget 识别的软件（Upscayl，NSIS 安装包），任务立刻显示“卸载程序已结束，但这个软件还在本机”。
2. 点重试，任务显示“已跳过：已不在本机”。
3. 软件要等整个队列结束、本机列表重新读取后才从列表里消失；这个任务也不能查找残留。

日志：winget 输出“已成功卸载”，紧接着 `[AppShelf] 之后的状态：仍在本机`。

## 原因

- NSIS、Inno Setup 的卸载程序把自己复制到临时目录后立即退出，由副本删除文件和注册表项。注册表卸载命令的路径有 `settle()` 等副本结束；winget 路径直接返回，复查早于副本完成。
- 重试前的检查发现程序已不在，按“第一次就不在”处理成跳过。
- `dropRemoved()` 和查找残留只认成功的卸载任务。

## 方案

1. **winget 卸载后也等卸载程序结束**（`internal/uninstall/run.go`）：winget 返回后报告“正在等待卸载程序结束”并调用 `settle()`。有注册表项时按注册表项判断是否已移除；没有时用 winget 复查。等待规则不变：副本还在运行就等（最多 30 分钟），副本结束后再等最多 5 秒。
2. **重试时程序已不在算卸载成功**（`internal/queue/queue.go`）：重试过的卸载任务做标记；执行前检查发现程序已不在时判为成功，说明“上次卸载其实已经完成”，并报告给执行方（刷新清单里对应软件的状态）。第一次排队前就不在的仍是跳过。
3. **跳过的卸载任务也立刻移出列表**（`internal/api/app.go`）：卸载任务只有“已不在本机”一种跳过原因，与成功一样立刻从本机已装列表中去掉。

## 不变量

- 仍以执行后程序是否还在判断成败；重试时已不在，说明上一次卸载已经生效。
- 查找残留仍只对成功的卸载任务开放；第一次排队就已不在的跳过任务不开放。
- 安装、更新任务的判断不变。

## 验收

- `internal/uninstall`：winget 返回时副本仍在运行，`Run` 等到副本结束、程序消失后才返回（有注册表项和没有两种情况）。
- `internal/queue`：失败的卸载重试时程序已不在，判为成功并调用 `Finished`；未重试的仍判为跳过。
- `internal/api`：跳过的卸载任务结束后，列表立即去掉该程序。
- `gofmt -l .`、`go vet ./...`、`go tool mygo vet`、`CGO_ENABLED=0 go test ./...`、`bun run --cwd frontend check`、`bun run --cwd frontend test`、`go tool mygo build`。
- 用户验收：用一个 NSIS 打包的 winget 软件真实卸载，第一次即显示已卸载并立即从列表消失。

## 回滚

三处改动互相独立，可以单独还原对应文件。
