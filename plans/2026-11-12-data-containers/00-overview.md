# 应用容器内并列数据目录识别

状态：`[in-progress]`

## 目标与规则

补齐程序与数据位于同一应用容器的情况，不使用软件名称白名单。只读空间归属继续与卸载残留清理分离。

- 从安装目录出发，仅沿通用程序目录（Apps、bin、current 等）和版本目录向上，最多四层；容器须位于现有数据根目录内。
- 排除共享目录、发布者公共目录、链接、受保护路径及包含其他软件安装的容器。
- 仅识别容器中有明确数据语义的直接子目录，不把任意兄弟目录或旧版程序当数据。
- 候选继续经过 FindData 的保护与 API 去重；不更改安装、卸载和清理规则，不扩大到全盘搜索。

## 验证与交付

覆盖本地化名称、多层和版本布局、名称不相似的软件、共享发布者、其他安装、保护目录、链接、取消和重复计数。运行 Go/前端检查和打包；用剪映安装元数据做只读核对。真实窗口由用户检查，预期看到 User Data 及占用，程序目录不重复计入数据。

## 风险与回滚

目录结构是归属线索，展示为“可能相关”；自定义名称、数据根目录外的路径保持未识别。回退本次查找实现及测试即可，无数据迁移。
